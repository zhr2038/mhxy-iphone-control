# App 状态与动作配方

本机实时缓存 → 局部 OCR/状态条件 → 批量动作。坐标是动作参数，不是状态证明。未识别状态返回错误和截图，交给模型，不能继续盲执行。

## 微信文件传输助手

配方名 `wechat-filehelper`：

```json
{"segments":[{"pinyin":"zhongwen","text":"中文"},{"pinyin":"yanshi","text":"演示"}],"send":false}
```

当前用户明确要求发送时才设 `send:true`。流程为：验证主屏幕 → 打开微信 → 聊天列表 → 搜索并选择内置“功能”入口 → 核对助手标题 → 点击输入框 → 保留既有草稿 → 中文候选逐段验证 → 逐字读回正文、再核对收件人 → 已授权则发送 → 检查输入框清空并返回截图供核验消息气泡。

区域（左上右下）：标题 `[20,100,698,176]`；功能结果 `[20,290,690,410]`；候选 `[0,960,718,1052]`；展开键盘后的输入框 `[85,800,560,885]`。

段支持 `pinyin/text` 或 `{"literal":"ASCII"}`。这不是任意 Unicode 直输通道。中文标点、换行、emoji 不得假定 ASCII 固件可原样输入。OCR 不确定或原文读回不符时停在草稿，查看截图，不静默删改用户原文。

## 新建备忘录与两列表格

配方名 `notes-create`：

```json
{
 "title":[{"pinyin":"shouji","text":"手机"},{"pinyin":"kongzhi","text":"控制"},{"pinyin":"yanshi","text":"演示"}],
 "paragraphs":[[{"pinyin":"zhongwen","text":"中文"},{"pinyin":"neirong","text":"内容"}]],
 "rows":[
  [[{"pinyin":"xiangmu","text":"项目"}],[{"pinyin":"zhuangtai","text":"状态"}]],
  [[{"pinyin":"wenzi","text":"文字"}],[{"pinyin":"yiwancheng","text":"已完成"}]],
  [[{"pinyin":"biaoge","text":"表格"}],[{"pinyin":"yiwancheng","text":"已完成"}]]
 ]
}
```

通过主屏幕搜索定位备忘录，点击原生新建按钮，确认空白才输入。第一行为标题；正文分段；原生表格默认两列，Tab 换格及追加行。点击 Done，最终截图核对标题、全文、原生网格和各单元格。

保留已有笔记；不能仅因快捷键 ok 就向未知编辑页输入。Cmd+N 在此手机未生效。按钮、中文、原生表格与 Tab 操作已有实机证据；整条自动配方仍须通过状态检查和最终视觉验收。

## 非配方操作

`screenshot` 和 `ocr` 使用 MHXY-PC 原始画面坐标。竖屏实测 332×720，指针归零约 `(52,0)`，每单位约 1.75 像素。上文配方区域使用内部归一化的 718×1560 坐标。先确认当前画面，重新归零定位。GUI 动画通常需 0.5–1 秒稳定等待。收件人、正文和提交结果都要验证。
